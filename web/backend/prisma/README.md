# prisma

## Purpose
This directory contains the Prisma schema, database migrations, and seed script for the OptiAgent backend's PostgreSQL database. The Node.js/Express backend is the sole owner of this schema; the Python AI service manages its own database schema through Alembic migrations independently and does not share this Prisma schema or this database.

The schema defines the persistent data models required for the backend's current feature set. Migrations are generated and applied with the Prisma CLI and are committed to source control so that the full migration history is reproducible in any environment.

## Responsibilities
- Defining the `User`, `Role` (as an enum), and `AuditLog` models in `schema.prisma`
- Configuring the Prisma datasource to connect to PostgreSQL via the `DATABASE_URL` environment variable
- Generating the Prisma Client used throughout `src/infrastructure/database/` and `src/modules/*/infrastructure/`
- Tracking all schema migrations as versioned SQL files in the `migrations/` subfolder
- Providing a `seed.ts` script that populates a local development database with the standard four roles (via the Role enum) and a set of demo users covering each role

## Does NOT Contain
- Application business logic
- Python AI service models (the Python service uses Alembic in its own directory)
- Redis data structures (Redis state is ephemeral and schema-free)
- Frontend or React code
- Environment variable files (`.env` is gitignored; `.env.example` is provided at the backend root)

## Architecture Position
```
[prisma/schema.prisma]
        |
   prisma migrate dev       ← generates SQL migration files and applies them
   prisma generate          ← generates Prisma Client into node_modules
        |
[src/infrastructure/database/prisma.service.ts]
        |
[modules/users/infrastructure/user.prisma.repository.ts]
[infrastructure/audit/audit-log.service.ts]
        |
      PostgreSQL

Python AI service ← separate database, separate Alembic migrations (not here)
```

## Expected Contents
- `schema.prisma` — Datasource block (provider: postgresql, url: env("DATABASE_URL")), generator block (client: prisma-client-js), and model definitions:
  - `User` — id, email (unique), passwordHash, firstName, lastName, role (Role enum), isActive (default true), createdAt, updatedAt.
  - `Role` — Prisma enum mirroring the four values from `@optiagent/shared`: EMPLOYEE, HR_MANAGER, FINANCE_ADMIN, IT_ADMIN.
  - `AuditLog` — id, action, entityType, entityId, actorId, actorRole, metadata (Json), createdAt.
- `migrations/` — Versioned SQL migration files generated by `prisma migrate dev`. Each migration folder is named with a timestamp and a descriptive label.
- `seed.ts` — TypeScript seed script executed via `prisma db seed`; creates the four standard demo users (one per role) with known development passwords; idempotent (uses upsert).

## Design Principles
- Single Responsibility: this directory exclusively manages database schema definition and migration; it contains no application logic.
- Separation of Concerns: schema ownership is clearly bounded to the Node.js backend; the Python AI service's data concerns are entirely separate.
